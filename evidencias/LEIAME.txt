Índice das evidências reais de execução local (AWS SAM CLI 1.174.0 + Docker Desktop 29.6.2):

1. 01-ambiente-sam-build.txt / .png
   Verificação do ambiente (`sam --version`, `docker --version`, `docker info`),
   validação do template (`sam validate --region us-east-1`) e build (`sam build`).

2. 02-invoke-evento.txt / .png
   Passo 3: duas execuções sequenciais de `sam local invoke -e events/pedido.json`
   com métricas (`Init Duration`, `Duration`, `Billed Duration`) e tempo total de relógio.

3. 03-start-api-sem-warm.txt / .png
   Passo 4a: `sam local start-api` padrão + 3 chamadas `POST /guias` (`R-002`, `H-Caruaru`),
   evidenciando `invocacaoNesteAmbiente` = 1, 1, 1 (um contêiner novo por requisição).

4. 04-start-api-warm-lazy.txt / .png
   Passo 4b: `sam local start-api --warm-containers LAZY` + 3 chamadas `POST /guias`,
   evidenciando reaproveitamento de contêiner (`invocacaoNesteAmbiente` = 1 -> 2 -> 3).

5. 05-timeout-3s-vs-10s.txt / .png
   Passo 5: falha de timeout com `Timeout: 3` (`502 Bad Gateway` / `timed out after 3 seconds`)
   e sucesso após alterar para `Timeout: 10` + `sam build` (`201 Created`, `5122.80 ms`).
